The problem

The company operated two Microsoft 365 tenants: its own and one for a client business it runs operations for. Licenses had been bought over time without a clear owner, so the subscriptions on the bill did not match what users actually had assigned.

At the same time, agents needed mailboxes to sign in to their daily apps, managers wanted control over who could email large groups, and IT needed self-service tooling without paying for Premium connectors.

Objective: Bring licensing under control, tighten access and mail flow, and deliver useful internal tools using only the licenses already owned.

Step by step

1

Audit every license against real usage

Licensing is usually the biggest controllable cost in Microsoft 365, and nobody notices waste until someone counts.

  • Pulled purchased versus consumed units for every subscription, including Entra ID P1, Power Automate Premium and Windows E3 VDA.
  • Compared assignments against what each role actually uses day to day (agents need email, a browser and a headset).
  • Found significant over-licensing on several SKUs and documented consolidation options with their trade-offs.
  • Presented the findings so leadership could decide which subscriptions to reduce at renewal.
# Purchased vs. assigned per SKU (Microsoft Graph PowerShell) Connect-MgGraph -Scopes "Organization.Read.All" Get-MgSubscribedSku | Select-Object SkuPartNumber, @{n='Purchased';e={$_.PrepaidUnits.Enabled}}, @{n='Assigned';e={$_.ConsumedUnits}}, @{n='Unused';e={$_.PrepaidUnits.Enabled - $_.ConsumedUnits}} | Sort-Object Unused -Descending

Best practice: license by role, not by person

Define a standard license bundle per job role. New hires get the bundle for their role, and audits become a simple comparison instead of an investigation.

2

Cut licenses from 50 to 25 with shared mailboxes

Many licensed accounts were not really people. Teams were signing in to a shared email address, and each of those accounts was paying for a full license.

  • Identified the accounts used as shared logins rather than by one person.
  • Converted them to shared mailboxes, which need no license, and gave the right users access to them.
  • Removed the freed licenses, bringing the count from 50 down to 25.
  • Users now open the shared inbox from their own account, so every action is tied to a real person instead of a shared password.
# Convert a shared-login account to a shared mailbox Set-Mailbox -Identity "support@example.com" -Type Shared # Give the team access from their own accounts Add-MailboxPermission -Identity "support@example.com" -User "Support Team" ` -AccessRights FullAccess -AutoMapping $true Add-RecipientPermission -Identity "support@example.com" -Trustee "Support Team" ` -AccessRights SendAs -Confirm:$false # Then remove the license from the converted account

Best practice: no shared passwords

Shared mailboxes save money and improve security at the same time: nobody shares a password, and the audit log shows who sent what.

3

Manage identity and access in Entra ID

  • Handled user lifecycle in Entra ID: creation, mailbox provisioning, group membership and offboarding.
  • Used a separate administrator identity for the second tenant so daily accounts never carry admin rights there.
  • Confirmed the agents' enrollment software supports single sign-on with OAuth2 / OpenID Connect against the company identity provider, as a path to fewer passwords.
  • Contributed to the bring-your-own-device security program, with HIPAA and SOC 2 as the compliance drivers.
4

Control mail flow in Exchange Online

  • Restricted which people can send to large distribution lists and Microsoft 365 groups, after operations asked to stop unwanted mass emails to agents.
  • Required senders to be authenticated so outside addresses cannot email internal groups.
  • Worked on SPF and DMARC records with the email security gateway as part of the domain hardening effort.
# Allow only approved senders to post to a distribution list Set-DistributionGroup -Identity "All Agents" ` -AcceptMessagesOnlyFromSendersOrMembers "Ops Leads" ` -RequireSenderAuthenticationEnabled $true # Same idea for a Microsoft 365 group Set-UnifiedGroup -Identity "Agents" ` -AcceptMessagesOnlySendersOrMembers "Ops Leads"

Precaution: test with a non-approved account

After applying a restriction, send a test from an account outside the allowed list and confirm the bounce message, so nobody is surprised.

5

Build an IT Directory in SharePoint with a custom SPFx web part

  • Created a SharePoint Communication Site to host IT resources.
  • Developed a custom SharePoint Framework web part in React and TypeScript using PnPjs v4, with live search, a styled results table and one-click copy per row.
  • Solved PnPjs v4 query syntax changes, SharePoint internal column names and strict TypeScript typing issues along the way.

Lesson: always query internal column names

SharePoint shows display names in the UI, but the API needs internal names, which can differ if a column was renamed. Check them in list settings before writing queries.

6

Ship a self-service troubleshooting hub on Power Platform

  • Built a Power Apps canvas app embedded in SharePoint that walks agents through headset and call-quality checks, with a free-text path for anything else.
  • Stored each session in a SharePoint list and screenshots in a document library, creating an audit trail before a ticket ever reaches IT.
  • Automated logging and notifications with five Power Automate flows.
  • Used standard connectors only, so it runs on Business Standard with no Premium licensing.
7

Apply retention to sensitive files

  • For a workflow that handles uploaded documents, files are moved out of chat into SharePoint within minutes and automatically deleted after three days.
  • Kept short, defined retention windows for request data, so sensitive information does not pile up in collaboration tools.

Outcome

  • Microsoft 365 licenses reduced from 50 to 25 by converting shared logins to shared mailboxes.
  • A clear, per-SKU view of remaining license waste with consolidation options for renewal.
  • Mass-email restrictions in place on agent distribution groups.
  • An IT Directory with a custom React web part that staff use instead of asking for numbers.
  • A no-Premium self-service app that sends IT tickets with evidence attached.
  • Short, automatic retention for sensitive uploaded files.
