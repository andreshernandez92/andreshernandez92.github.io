The problem

A colleague had built a Slack app that agents use to request approvals during a sale. It worked, but uploaded documents stayed in Slack for days and the processing ran inside a tool not meant to hold sensitive data. The app was handed to me to maintain and improve.

Objective: Keep the familiar Slack front end for agents, move processing to the cloud, and shrink how long sensitive data exists anywhere.

Step by step

1

Assess the existing app

  • Mapped every Slack interaction, input and output the agents and managers rely on.
  • Identified where sensitive data was stored and for how long.
2

Choose the platform

  • Evaluated Power Apps and Power Automate and ruled them out for this workload.
  • Chose Azure Functions for serverless processing, with approval to use Azure for the build.
  • Kept the logic as plain, deterministic code with no AI, so results are predictable and easy to audit.
3

Build it safely beside the live app

  • Ported the whole app to Azure Functions on a trial subscription using test data only.
  • Registered it as a separate Slack app so the live workflow was never at risk during development.

Best practice: never develop on the production app

A second Slack app with its own tokens lets you test freely and switch over only when it is proven.

4

Minimize sensitive data

  • Uploaded documents are moved out of Slack into SharePoint within minutes and deleted from SharePoint after three days.
  • Request data kept in Azure is also retained for three days only.
  • Manager-facing results in Slack show only what managers need to act.
5

Plan the final hosting decision

  • Prepared the working trial so leadership can choose final hosting with real results in hand, with the rule that sensitive data must not live in Slack.

Outcome

  • A working serverless version of the app running beside the original.
  • Sensitive files out of Slack within minutes instead of days.
  • Defined three-day retention for files and request data.
  • A clear path to production hosting, decided with leadership.
